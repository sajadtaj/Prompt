
این یک لیست گلچین‌شده و کاربردی از مهم‌ترین کامندهای این ابزار است :
+ Graphify
+ Segrep
+ Ruff

---

### 🕸️ ۱. Graphify (تحلیل ساختار و وابستگی‌ها)

*هدف: درک معماری فعلی، پیدا کردن فایل‌های وابسته، و به‌روزرسانی گراف بدون مصرف توکن.*

| کامند                                          | کاربرد برای انسان                                                                                                                                 | کاربرد برای ایجنت (Cline)                                                                                                                                                                                                         |
| :-------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graphify extract . --code-only`                  | **شروع کار:** ساخت گراف اولیه فقط از کدها (بدون فایل‌های ignore شده).                                          | ایجنت باید**فقط یک بار** در ابتدای پروژه این را اجرا کند تا `graph.json` ساخته شود.                                                                                                  |
| `graphify affected "src/old_file.py"`             | **تحلیل تاثیر:** می‌فهمد اگر این فایل را تغییر دهم/حذف کنم، چه فایل‌های دیگری می‌شکنند. | **حیاتی‌ترین کامند برای ایجنت.** قبل از هر `mv` (جابجایی)، ایجنت باید این را بزند تا لیست فایل‌های نیازمند آپدیت ایمپورت را پیدا کند. |
| `graphify update .`                               | **همگام‌سازی:** آپدیت کردن گراف بعد از جابجایی فایل‌ها (بدون نیاز به LLM).                             | ایجنت باید**بلافاصله بعد از هر جابجایی فایل** این را اجرا کند تا گراف با ساختار جدید سینک شود.                                                                     |
| `graphify explain "src/file.py"`                  | **درک سریع:** توضیح متنی و ساده از اینکه این فایل چیست و به چه چیزهایی وصل است.                   | ایجنت به جای خواندن کل فایل برای "فهمیدن کارکردش"، این را اجرا می‌کند و با چند خط توضیح، Context را درک می‌کند (صرفه‌جویی عظیم در توکن).      |
| `graphify path "A.py" "B.py"`                     | **بررسی مسیر:** آیا فایل A به فایل B وابسته است؟ (پیدا کردن مسیر وابستگی).                              | برای ایجنت مفید است تا قبل از جابجایی، مطمئن شود که لایه Domain به Infrastructure وابسته نیست (بررسی نقض Clean Arch).                                                           |
| `graphify query "Where are the database models?"` | **جستجوی معنایی:** پرسیدن سوال به زبان طبیعی از گراف.                                                               | ایجنت می‌تواند برای پیدا کردن محل دقیق فایل‌های مرتبط با یک فیچر خاص، به جای grep کردن کل پروژه، این را بپرسد.                                               |

### 🛡️ ۲. Semgrep (نگهبان قوانین معماری)

*هدف: جلوگیری از نقض قوانین Clean Architecture (مثل وابستگی لایه Domain به Infrastructure) و پیدا کردن Anti-patternها.*

| کامند                                     | کاربرد برای انسان                                                                                                                          | کاربرد برای ایجنت (Cline)                                                                                                                                                                                                                  |
| :--------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `semgrep scan --config .semgrep.yml --quiet` | **چکاپ سریع:** اجرای سریع قوانین و فقط نشان دادن خطاها بدون لاگ‌های اضافی.                  | ایجنت بعد از هر ریفکتور این را می‌زند. اگر خروجی خالی بود، یعنی معماری نقض نشده است.                                                                                                    |
| `semgrep scan --config .semgrep.yml --json`  | **خروجی خام:** دریافت خطاها در فرمت JSON.                                                                                  | **حیاتی برای ایجنت.** ایجنت به جای خواندن متن رنگی، JSON را پارس می‌کند تا دقیقاً بفهمد در **کدام خط** و **کدام فایل** قانون نقض شده است. |
| `semgrep scan --config auto`                 | **اسکن خودکار:** استفاده از قوانین پیش‌فرض Semgrep برای پیدا کردن باگ‌های رایج پایتون. | برای ایجنت مفید است تا مطمئن شود حین ریفکتورینگ، باگ سینتکسی یا منطقی رایجی ایجاد نکرده است.                                                                                   |
| `semgrep validate --config .semgrep.yml`     | **دیباگ قوانین:** بررسی اینکه آیا فایل `.semgrep.yml` که نوشتیم سینتکس درستی دارد یا نه.   | اگر ایجنت خواست قوانین جدیدی به فایل config اضافه کند، اول این را می‌زند تا از صحت آن مطمئن شود.                                                                                    |

### 🧹 ۳. Ruff (لینتر، فرمتر و تعمیرکار ایمپورت‌ها)

*هدف: مرتب‌سازی خودکار ایمپورت‌ها، پیدا کردن ایمپورت‌های شکسته‌شده پس از جابجایی، و تمیز نگه داشتن کد.*

| کامند                                         | کاربرد برای انسان                                                                                                                                                 | کاربرد برای ایجنت (Cline)                                                                                                                                                                                                                                          |
| :------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ruff check . --fix`                             | **تعمیر جادویی:** پیدا کردن و رفع خودکار خطاهای قابل رفع (مثل مرتب‌سازی ایمپورت‌ها با قانون `I`). | **بهترین دوست ایجنت در ریفکتورینگ.** بعد از جابجایی فایل‌ها، ایجنت این را اجرا می‌کند تا Ruff به صورت خودکار ایمپورت‌های شکسته و مرتب‌نشده را فیکس کند. |
| `ruff check <file> --output-format=json`         | **گزارش دقیق:** دریافت خطاهای باقی‌مانده در فرمت ماشین‌خوان.                                                                | ایجنت بعد از`--fix` این را اجرا می‌کند. اگر خطایی ماند، از روی JSON دقیقاً می‌فهمد کدام `import` هنوز خراب است و فقط همان خط را با `replace_in_file` درست می‌کند.            |
| `ruff check . --select I --fix`                  | **فقط مرتب‌سازی:** اجرای فقط قانون Isort (مرتب‌سازی ایمپورت‌ها).                                                               | اگر ایجنت فقط می‌خواهد ایمپورت‌های یک فایل شلوغ را مرتب کند بدون اینکه دستورات دیگر را تغییر دهد، از این استفاده می‌کند.                                                        |
| `ruff rule <CODE>` (مثلا `ruff rule F401`) | **آموزش:** توضیح می‌دهد که یک کد خطای خاص (مثل F401 یعنی ایمپورت استفاده نشده) دقیقاً چیست.                | اگر ایجنت با خطایی مواجه شد که نمی‌دانست چگونه رفعش کند، این کامند را می‌زند تا دلیل خطا را بفهمد (به جای حدس زدن و مصرف توکن).                                                 |
| `ruff format .`                                  | **فرمت‌دهی نهایی:** زیبا کردن کد (مثل Black).                                                                                                    | در مرحله آخر ریفکتورینگ، ایجنت این را اجرا می‌کند تا کدهای جابجا شده از نظر ظاهری یکدست شوند.                                                                                                          |

### 💡 Cheat Sheet (برگه تقلب) برای فایل `AGENT.md`

شما می‌توانید این بخش را مستقیماً در فایل `AGENT.md` که قبلاً ساختیم کپی کنید تا ایجنت دقیقاً بداند از کدام فلگ‌ها استفاده کند:

```markdown
## 🛠️ Tool Command Cheat Sheet (Use EXACTLY these flags)

### Graphify (Structure & Dependencies)
- Build initial graph: `graphify extract . --code-only`
- Find broken files before move: `graphify affected "path/to/file.py"`
- Sync graph after move: `graphify update .`
- Understand file without reading: `graphify explain "path/to/file.py"`

### Semgrep (Architecture Rules)
- Quick human check: `semgrep scan --config .semgrep.yml --quiet`
- Agent parsing (CRITICAL): `semgrep scan --config .semgrep.yml --json`

### Ruff (Imports & Syntax)
- Auto-fix imports after move: `ruff check . --fix`
- Agent parsing for remaining errors: `ruff check . --output-format=json`
- Understand an error code: `ruff rule <ERROR_CODE>`
```

این لیست به ایجنت (مخصوصاً مدل‌های سریع‌تر) دقیقاً "نقاط ورود" و "نقاط خروجی" ابزارها را نشان می‌دهد و او را از آزمون و خطا بی‌نیاز می‌کند.
